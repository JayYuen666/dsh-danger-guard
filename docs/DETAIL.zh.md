# 危险命令拦截

在破坏性命令动手前拦下它，并要求一个文件在本会话第一次被修改前先留下证据。

## 设置卡上改的是什么

- **拦截** — `enabled`（默认开）关掉后所有命令直接放行；`factGateEnabled`（默认开）要求某文件第一次被改前先读过它、并做过一次引用检索，严格程度按风险档走。
- **判定与放行** — `judgeStats`（默认开）把每次判定的耗时与输入规模攒成宿主日志里的一行滚动摘要（每 200 次一条），并在装了 lesson-loop 时随 `judge-cost` 每次判定各发一条 pass 样本，样本只有面名、毫秒、字符数，不含命令原文与路径；关掉只是不再看这些分布，判定一字不变。`maxDenies`（1–5，默认 2）是同一目标连续「未收敛」拒绝的次数上限，超过这个次数才配额放行并告警；缺项里仍有「读文件」时不放行——那是配额唯一不免的一项证据。判定不可行时走交互式确认，不消耗次数。`strictMode`（默认关）开了就不看写面风险分档，每个代码文件首次编辑都跑完整探查；两种情况下文档扩展名与非编辑工具都不进门禁。
- **分级规则** — `smallEditChars`（200）是低档含等号的上限，`bigEditChars`（2000）是高档不含等号的下限：恰好 200 字符算低档，恰好 2000 算中档。大小从不单独定档——新建文件、触及导出签名、manifest/lockfile/装配路径，以及取不到写面大小，都升到高档。低档只要求 `read`，引用检索从中档起要求，层探查只在高档要。`refSearchTools`（`grep`、`glob`、`zg_search`）列出哪些工具算引用检索证据；只写进 `refSearchStrictTools`（`zg_search`）的名字不产任何凭证，那一栏只负责把「根目录 + 路径签名」的严格口径打开。`smallEditChars` 不小于 `bigEditChars` 时中档不可达，这一对整体回落内置阈值并只告警一次。
- **你自己的词表** — `extraTestDirs`、`extraDevServerWords`、`extraDevRunArgs` 扩充测试层目录、开发服务器与开发命令的识别；`extraSecretPatterns` 追加密钥正则，在设置条目装配时逐条校验并编译，校验不过的那条不生效、并在日志里点名；装配之后才写进来的同一串也只报一次。

卡上这些档都是每次判定现读，改完下一次调用就生效，不需要重启宿主。

## 卡上没有旋钮的值

卡上能改的值都不需要重启：写入后下一次判定就按新值读。

有一档卡上没有旋钮：`preflightEnabled` 标了即时生效，但设置条目以 `auto: false` 注册表单。要改它只能走设置行的 `config:`。

## 需要外部提供什么

不需要任何本插件给不了的东西：没有外部 CLI、没有解释器、没有凭据。`zg_search` 只有在装了「Zvec 索引检索」插件时才存在。
